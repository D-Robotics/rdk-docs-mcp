## Concrete failure/overclaim traps exposed

1. Default network transport fails today with explicit rate limit: fresh users cannot obtain catalog through that path until available. Alternative transport success must not hide this.
2. Taking the first camera candidate as a dropped-frame specialist would be unsupported: fetched body stops at recognition/first-frame verification.
3. Taking the first S100 workflow candidate as complete training, compilation and deployment would be unsupported: fetched adaptation body covers model adaptation only.
4. Choosing the first compiler before knowing actual artifact format could select the wrong input/output contract. Ranking cannot resolve this absent user facts.
5. Converting unknown-platform or null-classification results into “verified X5 compatibility” would contradict returned evidence. The legacy speech query's lexical matched-board label is not a classified compatibility guarantee.

These are concrete limits that the prescribed caller workflow can handle; they are not labeled code defects without a violated service contract. Successful metadata/content retrieval proves neither final-answer factual accuracy nor hardware execution. This acceptance did not run a separate autonomous final-answer model, official-document verification, package tests, or installation tests.
